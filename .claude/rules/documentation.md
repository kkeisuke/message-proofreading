# ドキュメント作成ルール

本プロジェクトのすべてのドキュメントに適用する。

## 編集の可否

- `requirements.md` と `design.md` は、変更を指示されたときだけ編集する
  - 実装とのずれを見つけたら、直さずに報告して判断を仰ぐ

## 読者の前提

- 読者は開発の経緯を知らないものとして書く
  - 判断の根拠は文書内に埋め込み、その文書だけで「なぜ」が追えるようにする
- コミットしないファイル・存在しないファイルに言及しない
  - 参照が必要なら、必要な事実そのものを文書に書く

## 文章

- 簡潔に記載する
- 1項目は1文にする
  - 複数の文が必要なら、ネストした箇条書きに分解する
- 本文の括弧書きは、意味の限定に必須なものだけ残す
  - 補足や根拠の詳細は末尾の脚注（`[^n]`）に移す
- メタ的・AI 的な表現を書かない
  - 例:「本書は単体で読める」
- 同じ内容の言い換えを繰り返さない。要点は一度だけ述べる

## 内容

- 要求は目的の抽象度で書き、実現手段（特定の技術名など）で書かない
  - 例:「React の学習」ではなく「新しい技術の学習」
- 機能は最小実装を優先し、複雑さを増やす機能はスコープ外に明記する
- ツールが管理する情報（バージョン番号など）を転記しない
- 文書の責務を超える内容を書かない
  - 例: 設計で決める論点を要件定義書に列挙しない
