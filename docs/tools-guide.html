ツール設定ファイル解説

メッセージ校正デスクトップアプリ（Tauri + React）の開発環境を構成する設定ファイルの説明書。 Task 1〜2（scaffold・ツール整備）完了時点の内容に基づく。

全体像 — 誰が何を管理しているか

mise（ツールのバージョン管理）
 ├─ node 24 ── pnpm（パッケージ管理・スクリプト実行）
 │              ├─ vite ────── 開発サーバー & ビルド（フロントエンド）
 │              ├─ typescript ─ 型チェック（tsc -b）
 │              ├─ oxlint ──── 静的検査（バグの芽を検出）
 │              ├─ oxfmt ───── コード整形
 │              ├─ vitest ──── 単体テスト
 │              └─ @tauri-apps/cli ─ Tauri の開発・ビルド指揮
 └─ rust 1.97 ─ cargo ─ Tauri 本体（src-tauri/）のコンパイル

役割の重複はない。mise が「ツールそのもの」を、pnpm が「JS ライブラリ」を、 cargo が「Rust ライブラリ」を管理する。 日常操作は pnpm dev（ブラウザ確認）と pnpm tauri dev（アプリ起動）の2つが起点。

mise.toml — ツールのバージョン固定

このプロジェクトに必要なツールとバージョンの宣言。

[tools]
node = "24.15.0"
pnpm = "latest"
rust = "1.97.1"
キー意味補足
nodeNode.js 24.15.0 を使うVite や pnpm の実行基盤。パッチまで固定して再現性を確保
pnpmpnpm の最新版を使うnpm の代替。依存の install スクリプトを既定で実行しないためサプライチェーン耐性が高い
rustRust 1.97.1 を使うTauri 本体（src-tauri/）のコンパイルに必要。mise 経由で導入済み（実体は ~/.rustup、バイナリは ~/.cargo/bin）

ディレクトリに入ると mise が自動でこのバージョンに切り替える。 別マシンでも mise install 一発で同じ環境が揃う。

package.json — 依存とコマンドの台帳

JS の依存パッケージ一覧と、開発で使うコマンド（scripts）の定義。

"scripts": {
  "dev": "vite",
  "build": "tsc -b && vite build",
  "tauri": "tauri",
  "lint": "oxlint src",
  "format": "oxfmt src",
  "format:check": "oxfmt --check src",
  "test": "vitest run --passWithNoTests"
}
コマンド何が起きるか使いどころ
pnpm devVite の開発サーバーが localhost:5173 に立つブラウザだけで UI を確認したいとき
pnpm buildtsc で型チェック → 通ったら Vite が dist/ に本番ビルド型エラーがあるとビルドが止まる（安全弁）
pnpm tauri dev内部で pnpm dev を起動し、Rust をビルドしてアプリウィンドウを開くデスクトップアプリとしての動作確認。日常の起点
pnpm lintoxlint が src/ を静的検査コミット前チェック
pnpm formatoxfmt が src/ を整形（書き換えあり）コードを書いたあと
pnpm format:check整形の必要があるか確認だけ（書き換えなし）CI・コミット前チェック
pnpm testVitest が *.test.ts を1回実行--passWithNoTests はテスト0件でも成功扱いにするフラグ（テスト未作成の現段階向け）
依存役割
react / react-domUI ライブラリ（dependencies = アプリ本体が使う）
@tauri-apps/plugin-httpTauri 経由の HTTP 通信。CORS 制約を受けず、LLM ランタイムに接続する要
@tauri-apps/clitauri dev / build の指揮者（devDependencies = 開発時のみ）
vite / @vitejs/plugin-reactビルドツールと React 対応
typescript型チェック
oxlint / oxfmt検査と整形。Vite 8 の基盤（Rolldown）と同じ oxc プロジェクト製
vitestテストランナー。Vite と設定を共有できる

vite.config.ts — ビルドとテストの設定

Vite（開発サーバー・ビルド）と Vitest（テスト）の共通設定。

/// <reference types="vitest/config" />
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [react()],
  clearScreen: false,
  server: { port: 5173, strictPort: true },
  test: { include: ['src/**/*.test.ts'] },
});
キー意味補足
plugins: [react()]JSX の変換と高速リロードを有効化Task 3 で TanStack Router のプラグインがこの前に追加される予定
clearScreen: falseVite が起動時にターミナルをクリアしないTauri 側のログ（Rust のビルド状況）が消えないようにする Tauri 定番設定
server.port: 5173開発サーバーのポートtauri.conf.json の devUrl と一致している必要がある
strictPort: true5173 が使用中なら別ポートに逃げず失敗する勝手に 5174 になると Tauri が接続できなくなるため、あえて即失敗させる
test.includesrc/ 配下の *.test.ts だけをテスト対象にする1行目の reference コメントは、vite の設定に test キーを書けるようにする型定義の読み込み

tsconfig.json — TypeScript の型チェック

型チェックの厳しさと、コードが動く環境の宣言。

{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true
  },
  "include": ["src"]
}
キー意味補足
target / libES2022 の構文・API と DOM API を前提にするWKWebView（Safari エンジン）は ES2022 に対応済み
module / moduleResolutionimport の解決方法を「バンドラに任せる」方式にVite を使うときの現代的な標準設定
jsx: react-jsxJSX を自動変換（import React 不要）React 17 以降の標準
strict: truenull チェックなど全ての厳格オプションを有効化プロジェクトのグローバル制約。ドメインロジックの信頼性の土台
noEmit: truetsc は型チェックだけ行い JS を出力しない変換は Vite の仕事。役割を分離している
skipLibChecknode_modules 内の型定義ファイルは検査しないチェック時間の短縮。自分のコードは全て検査される
noUnusedLocals / Parameters未使用の変数・引数をエラーにする消し忘れの検出

.oxlintrc.json — 静的検査のルール

oxlint が「何をエラーにするか」の宣言。

{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "categories": { "correctness": "error", "suspicious": "warn" },
  "ignorePatterns": ["src/routeTree.gen.ts"]
}
キー意味補足
$schemaエディタで補完・検証を効かせるためのスキーマ参照動作には影響しない
correctness: error「明確なバグ」カテゴリの違反をエラーにする例: 存在しない変数の参照、常に false になる比較
suspicious: warn「怪しいが誤検知もありうる」カテゴリは警告どまりビルドは止めず、目視判断に委ねる
ignorePatternsrouteTree.gen.ts を検査対象から外すTanStack Router が自動生成するファイル（Task 3 以降）。機械が書くものは検査しない

.prettierignore — 整形の除外

oxfmt に「このファイルは整形するな」と伝えるリスト。

src/routeTree.gen.ts

ファイル名が .prettierignore なのは、oxfmt が Prettier 互換のため Prettier の除外ファイルをそのまま読む仕様だから。 oxlint の除外（.oxlintrc.json）とは別系統なので、生成ファイルは両方に書く必要がある — これは Task 2 のレビューで実際に検出・修正された穴。

.gitignore — git 管理の除外

コミットしてはいけないものの一覧。

.DS_Store
node_modules/
dist/
src-tauri/target/
行理由
.DS_StoremacOS の Finder が勝手に作るメタデータ
node_modules/pnpm が復元できる（pnpm-lock.yaml が設計図）。巨大なのでコミットしない
dist/Vite のビルド出力。ソースから再生成できる
src-tauri/target/cargo のビルド出力。数 GB になることもある

逆に pnpm-lock.yaml と src/routeTree.gen.ts（生成物だが）はコミットする方針。

src-tauri/tauri.conf.json — アプリ本体の設定

デスクトップアプリとしての名前・ウィンドウ・ビルド手順・セキュリティの定義。

{
  "productName": "message-proofreading",
  "version": "0.1.0",
  "identifier": "com.tauri.dev",
  "build": {
    "frontendDist": "../dist",
    "devUrl": "http://localhost:5173",
    "beforeDevCommand": "pnpm dev",
    "beforeBuildCommand": "pnpm build"
  },
  "app": {
    "windows": [{ "title": "メッセージ校正", "width": 800, "height": 600, ... }],
    "security": {
      "csp": "default-src 'self'; connect-src 'self' ipc: http://ipc.localhost; style-src 'self' 'unsafe-inline'"
    }
  },
  ...
}
キー意味補足
identifierアプリの一意 ID（バンドル ID）既定値のまま。後で実際の ID に変更予定（レビュー指摘の後回し項目）
build.devUrl開発時に WebView が読み込む URLVite の 5173 と一致。tauri dev はまず beforeDevCommand（pnpm dev）を起動してからここに接続する
build.frontendDist本番ビルドで同梱するフロントの場所Vite の出力先 dist/ を指す
app.windows起動時のウィンドウ定義タイトル「メッセージ校正」、800×600、リサイズ可
app.security.cspWebView 内のコードが通信・読込できる先の制限下記参照。プライバシー要件（N1）の第二の防衛線

CSP の中身:

ディレクティブ意味
default-src 'self'スクリプト・画像などは自分のアプリ内からのみ読み込める。外部 CDN 等は不可
connect-src 'self' ipc: http://ipc.localhostWebView 自身の fetch は自分と Tauri の IPC のみ。外部サーバーへの直接通信は不可
style-src 'self' 'unsafe-inline'CSS は自前 + インラインを許可（React の style 属性等のため）
ポイント: LLM への通信（localhost:12434 など）はこの CSP に書かれていない。 それでも通信できるのは、実際の HTTP を WebView ではなく Rust 側（plugin-http）が行うから。 その Rust 側の通信先を縛るのが次の capability。

src-tauri/capabilities/default.json — 権限（最重要）

フロントエンドが Tauri の機能をどこまで使えるかの許可リスト。

{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    {
      "identifier": "http:default",
      "allow": [{ "url": "http://localhost:*" }]
    }
  ]
}
キー意味補足
windows: ["main"]この権限セットが適用されるウィンドウメインウィンドウのみ
core:defaultTauri の基本機能（イベント、ウィンドウ操作など）既定の最小セット
http:default + allowplugin-http での通信を http://localhost:* のみ許可ポートは任意（12434 = Model Runner、11434 = Ollama の両対応）。ホストは localhost 固定
二重の防衛線（設計 §1）: アプリのコードや依存パッケージに悪意あるコードが紛れても、 (1) WebView からの直接通信は CSP が塞ぎ、 (2) plugin-http 経由の通信は この capability が localhost 以外を拒否する。 「業務メッセージを外部に送らない」という要件（N1）を、実装の注意ではなく構成で保証している。
